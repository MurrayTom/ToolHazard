# IPI设计
我们现在已经有环境、原始任务、任务对应的一条轨迹、攻击点


### 1、生成注入计划
输入环境的介绍、限制，攻击点的信息，原始任务，让LLM思考如何在不影响原任务的执行下把注入任务注入进去
输出注入的位置与计划（注入位置指的是注入到哪个实体的哪个具体对象的哪个属性，注入计划是在利用现有工具怎么进行注入）

注入计划要注意注入的时候不能破坏原任务的可执行性，不能因注入了东西导致原本任务所需的关键内容消失，同时还要保证注入的位置会在agent执行原任务时被读到（即我们希望agent执行正常任务时读到污染数据从而被劫持做注入任务，但是污染数据不能把原任务的有用信息给搞没了）


### 2、生成需要注入的任务
输入原始任务以及init_config（假设可以知道环境的所有状态），环境的介绍、限制，还有根据轨迹筛选得到的攻击点
把这些输入大模型，首先生成需要注入的任务（任务至少包括写操作）
输出注入任务

LLM在生成时，要根据原有任务、环境的信息来确定注入的任务的内容，要做到与原本的环境同时注入任务与原任务应该是要做不同的事（不然不容易判断是否被劫持）相容且具有诱导性会容易让agent做别的。
此外还可以确定注入策略，例如在原内容与注入任务之间加上“忘掉之前的内容”之类的


### 3、执行注入
使用一个ReAct Agent执行，给到需要注入的任务，注入计划，环境的介绍、限制，攻击点的信息。
输出注入后的config

这一步最麻烦，我们需要有一个env和一个agent
